# Requirements — draft
AF01 configurable weekly room schedule, triggered by empty household. AF03 configurable per-room vacuum/mop frequency and profiles; simultaneous operation where supported. On-demand restricted rooms and manual preparation acknowledgement. AF04 presence-aware pause in place and resume of the same retained task; explicit abort and dock terminates the task; a subsequent start repeats the original full task scope after fresh validation; guest mode blocks automatic starts/resume. Per-person arrival handling and no-answer behavior remain open. AF09 immediate maintenance notifications where reliable signals exist; configurable repeat interval, clear on resolution, resume only verified retained paused tasks or authorize a fresh full-scope start after reconciled termination and validation. AF11 configurable events and recipients, including missed scheduled cleaning. AF12 admin UI for persistent policies, enable flags, status, validation and manual controls. No household-specific defaults mandated.
DK01 model capability profiles; DK02 validate combinations; DK03 controlled transitions; DK04 readback; DK05 accepted vs verified command; DK06 evidence-aware state; DK07 persistent logical and physical jobs; DK08 resume only a verified retained paused task; abort and dock terminates it; DK09 verified task-level completion (not inferred from docking or command acceptance); DK10 reapply profile per physical job.
Requirements are research inputs pending detailed acceptance criteria.

Proposed under #3: DK11 versioned approved robot/area-to-map and 1:N segment mapping; DK12 fresh inventory validation, scoped diagnostics and no automatic remapping; DK13 bind start/resume to approved revision and explicit segments, block unknown retained-task identity, completion or command outcome as applicable; no selective replay.
