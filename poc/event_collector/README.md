# HA Event Collector — POC12C offline review candidate
Python 3.13 / websockets 16.0 / Tkinter. Windows: `py -m pip install -r requirements.txt`, `py -m unittest discover -v`, `py app.py`.
The GUI supports exact entity selection, bounded synthetic capture, start/stop, message counts, local evidence and ZIP export. Choose a private local folder. The demo uses an in-process mocked transport; no network connection. Live capture is deliberately not wired into the GUI. The experimental coroutine is not approved for use against HA.
Authentication is excluded. Base64 preserves accepted application message bytes, not network packets. UTC and monotonic times are local observations. Freshness UNKNOWN. Unexpected entities are rejected before storage; rejected raw messages are not retained. Complete means bounded capture with acknowledgement and initial snapshot, not proof of device truth or event completeness. No automatic reconnect. Export checks count, sequence, aggregate and individual hashes. Hashes do not prove authenticity. Windows ACLs and crash durability are not enforced. Do not publish private captures.
Review gates: confirm exact HA version/source, scoped subscription schema and privileges; inspect failure cases and credential exclusion; test GUI on Windows; independently review exact revision and tests before owner approval. No live HA calls, installation, physical tests or dispatch authorized. B1 remains open; POC12B deferred. TEST_RESULTS.txt is historical; Claude independently confirmed 10/10 on the original revision. Subsequent changes require a fresh run.

## API baseline (B1)
Source reviewed by Claude: HA Core 2026.11.2, https://github.com/home-assistant/core/blob/2026.11.2/homeassistant/components/websocket_api/commands.py ; independent review https://github.com/Zotoca69/Smart-Cleaning-Manager/pull/9#issuecomment-7049253477 . Installed version must be confirmed before live use. subscribe_entities accepts id, type, entity_ids and optional include/exclude filters; this client uses only a nonempty exact ID list. Empty list can expose all entities. Listener registration precedes result acknowledgement and initial snapshot. Compact event keys a (added), c (changed), r (removed); changes use + and -; state keys include s (state), a (attributes), c (context), lc (last changed), lu (last updated). Removal ends capture as incomplete. No interpretation of duplicate events or device chronology. User read permission is checked initially and on changes; administrator/global read permissions may be broad. Token is not inherently read-only: application command restriction is the only write prevention here.
Frontend subscribeEntities is a useful existing state-oriented client but reconstructs state rather than providing a raw evidence ledger. Python clients such as hass-websocket-client are candidates for further evaluation, not verified replacements; generic websockets minimizes transformation and dependencies while retaining application bytes. No broad subscribe_events fallback. TLS required; local non-TLS access remains an unresolved deployment decision. Proxy disabled. No cloud connection authorized.
